# 0025. Packaging, apt repository and updates

Date: 2026-10-31 · Status: Proposed

## Context

Phase 6 ships NOCS two ways: a Raspberry Pi image (ADR 0026) and packages for PCs
running Ubuntu 26.04 (ADR 0007). Both should install the same files, so the image
is built from the packages. Facts that shape the decision:

- **Python.** nocsd needs Python 3.12 or 3.13: `sep` and other scientific
  dependencies have no arm64 wheels for 3.14, Ubuntu 26.04's own Python, and the
  appliance has no compiler ([spike](../spikes/pi5-performance.md)). uv installs
  standalone CPython builds (python-build-standalone) that need nothing but glibc.
- **Launchpad PPAs** build packages from source on Launchpad, without network
  access: they cannot carry the wheels nocsd depends on (OpenCV, NumPy, astropy,
  `sep`). Debian's own way, a package per Python dependency, would mean packaging
  dozens of libraries at versions Ubuntu does not have.
- **INDI and PHD2** come from their PPAs (`ppa:mutlaqja/ppa`, `ppa:pch/phd2`),
  which publish only for the current Ubuntu release and drop old versions.
- indiserver needs a driver FIFO that nocsd writes (ADR 0011), and the main
  camera's driver saves frames where nocsd reads and moves them (ADR 0012). PHD2
  imports the settings file nocsd writes (ADR 0022). Today the lab Pi runs all
  three as the maintainer's user, with template units in `dev/pi/`.
- Ubuntu Server enables **unattended-upgrades**, and **needrestart** restarts the
  services that use an upgraded library. At night that would restart indiserver
  in the middle of an exposure, or nocsd during a sequence.
- A PC is someone's computer: installing NOCS must not change its network. The
  appliance must take the network over (ADR 0028).

## Decision

### Packages

- **`nocs`** (amd64 and arm64) holds everything that runs on any computer:
  - `/opt/nocs/python`: a standalone CPython 3.13 installed by uv;
  - `/opt/nocs/venv`: nocsd and its locked dependencies (`uv sync --locked
    --no-dev --no-editable`), bytecode compiled;
  - `/opt/nocs/web`: the built web app;
  - `/opt/nocs/libexec/nocs-phd2`: PHD2's entrypoint (`dev/phd2/entrypoint.sh`);
  - systemd units `nocsd.service`, `nocs-indiserver.service` and
    `nocs-phd2.service` (and `nocs-system.service`, ADR 0027);
  - the system user **`nocs`** (sysusers.d, groups `dialout`, `plugdev` and
    `video`) and its directories (tmpfiles.d);
  - `/etc/nocs/nocsd.env`, a conffile with nocsd's settings.

  It depends on `indi-bin` and recommends `indi-3rdparty-drivers`, `phd2` and
  `xvfb`; ASTAP and its databases are installed as ADR 0018 says (`/opt/astap`).
- **`nocs-appliance`** (all architectures, later stages) makes a box the
  appliance: NetworkManager with the access point and its fallback, the firewall,
  nocsd on port 80, the host name, first boot and the operations of nocs-system
  that only make sense on a dedicated box. The image installs it; a PC never gets
  it unless someone asks for it.
- **indiserver, PHD2 and nocsd run as `nocs`.** The FIFO lives in `/run/indi`,
  the server's data in `/var/lib/nocs` (configuration, profiles and `auth.json` in
  `/var/lib/nocs/config`, the catalog, previews and frames from drivers next to
  them). nocsd's unit `Wants` the other two, so they start with it, and a restart
  of nocsd leaves indiserver and PHD2 running (ADR 0011, ADR 0022).
- Packages are **binary packages built with `dpkg-deb`** by
  `packaging/deb/build.sh` in an Ubuntu 26.04 container, natively on each
  architecture (GitHub's arm64 runners for arm64). The environment is created at
  its final path, `/opt/nocs`, so its scripts and `pyvenv.cfg` are right without
  rewriting. Maintainer scripts use `deb-systemd-helper` and `deb-systemd-invoke`,
  which honour `policy-rc.d`: nothing starts inside an image build.
- **Versions** come from `server/pyproject.toml`. Builds between releases are
  `X.Y.Z~git<date>.<commit>`, which sort before `X.Y.Z`.

### Repository

- One signed apt repository, generated by CI as static files, with two suites:
  **`stable`** (tagged releases) and **`testing`** (every push to `main`). The
  signing key lives in CI secrets; its public half is shipped in
  `/usr/share/keyrings/nocs-archive-keyring.gpg`, and a deb822 source names it
  with `Signed-By`.
- The host must take files of hundreds of megabytes and the image (over 2 GiB,
  ADR 0026); it is chosen in stage 6.10. Until then, packages are CI artifacts.
- PC installs add the INDI and PHD2 PPAs and the NOCS repository, then
  `apt install nocs`. The quick start says how.

### Updates

- **Only when the owner asks**, from the app, through nocs-system (ADR 0027), and
  **never while a job runs**: `apt-get update`, then an upgrade of the NOCS, INDI
  and PHD2 packages and of the OS, with the app showing progress. nocsd restarts
  at the end; indiserver and PHD2 restart only if they were upgraded.
- On the appliance, unattended-upgrades only **downloads**; needrestart only
  **lists** what would need a restart. The app shows that updates are waiting.
- **Rollback:** the previous `nocs` package stays in apt's cache; nocs-system can
  install it again. Before nocsd changes the format of its files (catalog,
  profiles, `auth.json`) it copies them aside, named after the version that
  wrote them, and a downgrade puts those copies back.
- Updating from a USB drive, for a box that never sees the internet, is left for
  later.

## Consequences

- One package and one layout on a PC and on the Pi; the image is the packages
  plus `nocs-appliance` (ADR 0026).
- `nocs` is large (a whole Python and OpenCV, around 120 MB compressed) and is
  built per architecture. Its Python and wheels are updated only with a new
  release of NOCS, which therefore has to follow security fixes in them.
- An INDI or PHD2 release from the PPAs reaches users only when they update, but
  NOCS cannot pin it: the PPAs keep only the newest version. Keeping tested copies
  in the NOCS repository is possible later if an upgrade breaks something.
- The lab Pi's template units (`dev/pi/*@.service`, running as the maintainer)
  stay for development; the packaged units replace them on boxes built from the
  image.
- On a PC, `nocs` serves port 8000 on every interface like the lab Pi does; the
  owner passphrase protects it (ADR 0014), and indiserver's and PHD2's ports are
  open to the network unless the PC's own firewall closes them.
